# 路线图

> 原则：每个里程碑结束时都有**可演示、可收费验证**的东西；先跑通商业闭环，再拓宽内容面。

## M0 · 骨架与钱包（起手 1–2 周）

**目标**：技术地基 + 商业模式的地基（积分账本）落地。

- Monorepo 脚手架：`apps/mobile`(Expo) / `apps/api`(Fastify) / `packages/{shared,ai-core,db}`
- 登录：手机号验证码（微信/Apple 登录排 M2）
- 钱包核心：注册送体验积分、充值（先接沙箱/人工通道）、账本、账单页
- 价目表 v1 落在 `packages/shared`，账单页可真实展示每笔明细
- CI：lint + test + 类型检查；部署脚本打通（api → 国内云）

**验收**：手机上装 App，注册即有余额，账单页看到赠送记录，账目对得上。

## M1 · 核心体验：AI 口语陪练（3–4 周）

**目标**：把「值回价签」的那一分钟做出来。

- ai-core：LLM/ASR/TTS 抽象层 + 首批供应商（方舟或百炼起步）+ 成本埋点
- 语音对话全链路流式（首字 < 1.5s），打断（barge-in）
- 3 个精品情景（中→英）：咖啡店点单 / 求职面试 / 旅行问路；AI 角色化、难度自适应
- 按分钟计费接入：对话前明示单价、结束出账单（消费 + 收获同屏）

**验收**：真实用户完成一次 10 分钟对话，付费扣账正确，复盘报告「下次开口就能用」。

### M1 交付进度（2026-09-28）

- ✅ ai-core 抽象层：LLM 流式统一接口 + OpenAI 兼容适配器（方舟/百炼/OpenAI 三通）+ CostMeter 成本埋点 + 任务分级路由（11 tests）
- ✅ 3 个精品情景（中→英）内容资产 + 质量门槛测试
- ✅ 会话服务 + **按秒累进计费**（水表模型：每个 turn/end 结清秒段、幂等、余额不足即时拦截）接入钱包（29 tests，全链路冒烟通过）
- ⏳ 语音传输（WS 流式 + barge-in）→ 拆到 **M1.5**（前置条件：ASR/TTS 供应商 Key）
- ⏳ 复盘报告 → M2（与生词本一起做，先有 SRS 落点再出报告）

## M1.5 · 语音传输与真机联调（1–2 周）

**目标**：把 M1 的文本回路升级为真·开口说话。

- WS `/v1/realtime` 双通道协议（控制帧 JSON + 音频帧 PCM，见 architecture.md §7.3）
- ASR/TTS 供应商接入与选型实测（延迟、音色、价格三项打分）
- VAD 断句 + barge-in 打断
- 真机联调：iPhone / 安卓各一台，端到端延迟达标（首字 < 1.5s）

**验收**：真机上和 AI 自然对话 3 分钟，打断它 3 次，它都接得住。

## M2 · 学习闭环与档案（2–3 周）

**目标**：终身学习的第一块砖——今天学的，下周还回得来。

- 复盘报告：纠错 / 更地道说法 / 生词提取（结构化落库）
- 生词本 + FSRS 复习（含复习动作的轻量 AI 精讲）
- 学习档案页：时长、开口次数、词汇增长、进步曲线
- 微信 / Apple 登录；数据导出

**验收**：用户隔 3 天回来复习，App 记得他上周说错的一切。

## M3 · 收费验证（2 周 + 运营持续）

**目标**：让陌生人真金白银付费，验证单位经济学。

- 正式支付：iOS IAP + 微信/支付宝；定价校准（真实成本报表 → 调价）
- 内容扩到 10 情景 × 3 语言对；应用商店提审
- 内测 50–200 人：付费转化率、单用户毛利、次周留存、延迟达标率
- 合规收尾：ICP 备案、隐私政策、语音数据删除通道

**验收**：存在「第三次充值」的用户——按量付费模式成立的最硬证据。

## 之后（MVP 验证成功再谈）

语言对横向扩展（英→中反向市场、对外汉语）、打字模式、沉浸式阅读听力、家长/教师端、B2B（机构按量采购）。
